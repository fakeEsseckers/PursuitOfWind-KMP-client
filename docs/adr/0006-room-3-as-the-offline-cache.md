# 0006. Room 3 as the offline cache

- Status: Accepted
- Date: 2026-10-22

## Context

The app has to answer "go or no-go" on a beach with one bar of signal, and show the last crew rides when there is none. Screens therefore read from a local cache that is the single source of truth, and the network only refreshes it (stale-while-revalidate). The cache must run on Android and iOS from common code, emit changes as `Flow`, survive restarts, and stay testable without a device. The brief named Room KMP; since then Room 3 became stable (3.0.0 in July 2026, 3.0.3 now): a new artifact group (`androidx.room3`) built on `SQLiteDriver` and coroutines only.

## Decision

- Room 3.0.3 with the bundled SQLite driver (`androidx.sqlite:sqlite-bundled`) in `:shared:data`, code generated by KSP 2.3.12 for every target. DAOs are `suspend` or return `Flow`; transactions use `withWriteTransaction`.
- The database is a cache, not a store of record: everything in it can be fetched again. Tables stay flat (lists such as sectors, model winds and passengers are stored as JSON in the contract's format), and a schema change without a migration drops the tables (`fallbackToDestructiveMigration`). Schemas are exported to `shared/data/schemas`.
- Each table has a `sync_state` row with the time of its last fetch, so screens can say "updated 2 h ago"; crew feeds also store their cursor there.
- Small values (the profile, the owner of the cache) live in DataStore Preferences; tokens in the platform secure store. The database, the settings file and the secure store are named after the environment, so fake, demo and real data never mix.
- Tests that need SQLite run in a `sqliteTest` source set shared by the JVM and iOS: the bundled driver loads there, but not in Android host tests, which resolve the Android variant and its device-only native library. Tests pass their dispatcher to Room and DataStore so optimistic updates can be observed between virtual-time delays.

## Alternatives considered

- Room 2.8 KMP — the same model and tooling, but Room 3 is where fixes and KMP work now land, and it drops the blocking `SupportSQLite` APIs this project would never use.
- SQLDelight — SQL-first and mature on KMP, with no annotation processing. Room keeps entities and queries in Kotlin, checks queries at build time against the entities, and is what Android teams already know; for a handful of tables that wins.
- DataStore or files only — enough for a profile, not for per-crew rides queried by departure time.

## Consequences

- Positive: the same DAO and repository code runs on Android, iOS and the JVM, and screens observe one `Flow` per screen whether data came from the network or not.
- Positive: a lost connection never empties a screen; the worst case is old data with its age.
- Negative: KSP adds a code-generation step per target to every build of `:shared:data`.
- Negative: Room 3 is young; KSP and AGP 9's KMP library plugin worked together here, but a toolchain upgrade can break that first.
- Negative: Room-backed tests do not run on the Android host runtime; the JVM run covers the same common code.
- Revisit when: data must survive app updates without being fetched again (then write migrations instead of dropping tables), or the cache needs full-text search or large queries.
